# 小红书小工具版设计

## 目标

基于 `8a0e909` 制作一个不影响 Netlify 生产站的独立小红书 Builder Hub 上传包。产物是根目录直接包含 `index.html` 的离线 ZIP，仅保留《欢乐颂》引导演奏与自由演奏。

## 官方容器约束

- 所有脚本、样式和图形资源必须在 ZIP 内，以相对路径加载。
- 禁止网络请求、外部资源、WebAssembly、Worker、iframe、动态执行代码及硬件连接 API。
- ZIP 只包含官方允许的静态文件类型，不包含源码映射、构建配置、测试产物或开发依赖。
- 页面使用 `viewport-fit=cover`、Pointer Events、安全区 `env()` 与移动端自适应布局。

## 产品差异

- 曲目目录仅导出 `ode-to-joy`，选曲页只有《欢乐颂》，所有“双曲目”和卡农文案删除。
- 保留方向节奏轨、三维弦乐器、实时 Web Audio、结算、重播和自由演奏。
- 小红书容器虽允许 `getUserMedia`，但现有手势识别依赖 MediaPipe WASM；因此小红书版移除摄像头模式、模型、WASM 和依赖，以触屏/鼠标 Pointer Events 为主输入，自动演示仅作验收入口。
- 首页与状态文案改为“触屏/鼠标”，明确离线运行、不上传数据。

## 构建与打包

- Vite 使用 `base: "./"`，生成相对资源路径；入口 viewport 包含 `viewport-fit=cover`。
- 构建目录只保留 `index.html`、CSS 和 JS；从目录内容打包，确保 ZIP 根目录直接是 `index.html`。
- 打包前扫描最终 `dist`：禁止 API、外部 URL、绝对资源路径、内联脚本、非法扩展名、缺失资源与超过 2MB 的总包。

## 验证

- 自动测试固定单曲目录、无 MediaPipe 依赖、无摄像头/卡农 UI、相对构建配置及 viewport。
- 运行全量 Node 测试和 TypeScript/Vite 生产构建。
- 在 390×844 与桌面视口验收首页、触屏自由演奏、欢乐颂节奏轨和结算流程。
- 解包复核 ZIP 顶层、文件白名单、禁用能力扫描和最终体积。

## 边界

本任务只产出可上传 ZIP，不登录或发布到小红书，不修订《D 大调卡农》，不部署或改动 Netlify 站点。
