# VSCO 真实提琴采样音色设计

日期：2026-07-22
状态：已确认

## 背景

当前 `StringSynth` 使用锯齿波、三角波、带通噪声和低通滤波构造弦乐感。它的响应速度适合手势控制，但缺少真实小提琴的琴体共振、弓头起音、力度层音色差异和自然颤音，因此听感更接近合成弦乐。

本轮改造把真实录音作为主音色，同时保留现有合成链路的低延迟与可靠性。选择的样本库为 VS Chamber Orchestra 2 Community Edition（VSCO 2 CE）Solo Violin / Arco Vib，官方以 CC0 发布，可随项目重新分发。SFZ 映射提供 `p`、`f` 两个力度层，覆盖当前项目的全部音域。

来源：

- https://versilian-studios.com/vsco-community/
- https://github.com/sgossner/VSCO-2-CE
- https://github.com/sgossner/VSCO-2-CE/tree/master/Strings/Solo%20Violin/Arco%20Vib
- https://raw.githubusercontent.com/sgossner/VSCO-2-CE/SFZ/SViolinVib.sfz

## 目标

- 默认音色由真实 Solo Violin 采样提供，而不是振荡器。
- 保留现有手势的即时反馈：拉弓速度控制响度和音色，换弓方向改变产生可听见的弓头起音。
- 引导演奏继续由 MIDI 决定基础音高，不改变节奏、计分和伴奏逻辑。
- 首次点击后先保证立刻有声音；采样未加载或加载失败时自动使用现有合成音色。
- 新增音频资源传输预算不超过 1.5 MB，避免明显增加移动网络等待。
- 正常设备上，音频链路本身不增加可感知的手势延迟。

## 非目标

- 本轮不实现物理建模小提琴。
- 不加入拨弦、跳弓、碎弓或多种奏法切换。
- 不修改伴奏音色、曲谱、计分规则、双手职责或视觉舞台。
- 不在未获得明确批准时覆盖 Netlify 生产站点。

## 方案比较

### 方案 A：VSCO 双力度真实采样与现有表达链路混合（采用）

优点是真实录音、CC0 授权、音域和力度层完整；可以保留现有弓噪声、滤波和实时增益映射。代价是需要处理采样加载、换音交叉淡化和长音续接。

### 方案 B：FluidR3 GM 浏览器 SoundFont

接入最快，也有清晰的 CC BY 3.0 授权，但音色偏传统 GM，力度层和弓法表达有限。它适合作为快速原型，不足以成为项目的目标音色。

### 方案 C：继续改进振荡器或做简化物理建模

资源最小、参数最灵活，但要达到真实独奏小提琴质感需要更复杂的弓弦和琴体模型，超出这一迭代的范围。

## 采样资产

下载地址固定到 VSCO 2 CE `1.1.0` 发布标签或明确的 Git commit，不从可变的 `master` 分支生成运行时资产。manifest 同时保存源 URL 和 SHA-256。

只选用当前可演奏音域需要的六个根音，每个根音包含 `p` 和 `f` 两层，共 12 个文件：

- C4：`LLVln_ArcoVib_C4_p.wav` / `LLVln_ArcoVib_C4_f.wav`
- E4：`LLVln_ArcoVib_E4_p.wav` / `LLVln_ArcoVib_E4_f.wav`
- G4：`LLVln_ArcoVib_G4_p.wav` / `LLVln_ArcoVib_G4_f.wav`
- A4：`LLVln_ArcoVib_A4_p.wav` / `LLVln_ArcoVib_A4_f.wav`
- C5：`LLVln_ArcoVib_C5_p.wav` / `LLVln_ArcoVib_C5_f.wav`
- E5：`LLVln_ArcoVib_E5_p.wav` / `LLVln_ArcoVib_E5_f.wav`

映射沿用官方 SFZ：D4 使用 E4 根音降两个半音，D5 使用 E5 根音降两个半音；其余当前音符均命中原始根音或位于官方映射范围内。最大转调不超过两个半音，避免明显的重采样失真。

导入脚本负责：

1. 校验源文件 URL 和 SHA-256。
2. 下混为单声道并保留 44.1 kHz。
3. 对源文件做一致的安全峰值归一化，保留 `p/f` 的音色差异；最终响度由运行时力度混合控制。
4. 编码为 128 kbps MP3，输出到 `public/audio/violin/vsco2-ce/`。
5. 生成包含根音、力度、时长、源哈希和输出哈希的 TypeScript manifest。
6. 将 CC0 许可证和来源说明写入仓库。

原始 WAV 不提交到 Git；压缩后的 12 个运行时文件提交。源 URL、哈希和转换参数保证可以重新生成。

## 音频架构

### 纯逻辑层

新增 `sampleVoiceModel`，只处理可测试的决策：

- 根据目标 MIDI 选择最近且符合官方范围的根音。
- 计算 `playbackRate = 2 ^ ((targetMidi - rootMidi) / 12)`。
- 将手势强度映射为等功率 `p/f` 混合增益。
- 判断何时需要新弓头：静音转发声、目标音变化或拉弓方向反转。
- 计算释放、换弓和长音续接的交叉淡化时间。

### 采样播放层

新增 `SampledViolinVoice`，使用项目已有的 `AudioContext` 和原生 Web Audio，不引入 Tone.js：

- 每个声音实例同时启动对应根音的 `p`、`f` 两个 `AudioBufferSourceNode`。
- 两层保持同相起播，并通过独立 `GainNode` 按强度平滑混合。
- 同一根音范围内移动时平滑更新 `playbackRate`，不重启采样。
- 音高跨出根音范围、声音从静音恢复或拉弓方向改变时启动新实例，并在 35 ms 内与旧实例交叉淡化。
- 采样接近尾部但手势仍在持续时，从该录音的稳态偏移点启动续接实例，用 90 ms 交叉淡化避免重复弓头和突然截止。
- 松手、跟踪丢失或停止拉弓时沿用约 110 ms 的自然释放。

### 表情与空间

- 手势强度同时控制 `p/f` 音色混合和总响度，避免只做音量变化。
- 保留当前松香噪声，但降到现有强度的约 20%，只用于强调弓毛摩擦，不再承担主体音色。
- Arco Vib 录音已包含自然颤音，因此默认关闭当前人工颤音 LFO，避免双重颤音。
- 使用代码生成的短房间脉冲响应代替明显的反馈延迟，脉冲生成采用固定种子，保证可复现且不增加外部资产。

### 合成回退与 A/B

现有振荡器链路保留为 `SyntheticStringVoice`：

- 第一次用户点击后立即启动合成链路，同时异步加载采样。
- 采样全部解码成功后，在 120 ms 内从合成音色交叉到真实采样。
- 任一必要采样加载或解码失败时继续使用合成链路，界面显示一次非阻塞提示，不让演奏静音。
- 默认使用采样；`?tone=synth` 强制旧音色，`?tone=sample` 强制采样优先，便于同一版本 A/B 验收，不新增永久 UI 控件。

## 数据流

`PerformanceState` 仍是唯一音频输入：

1. 摄像头、鼠标或自动演示产生 `PerformanceState`。
2. `StringSynth` 把状态同时交给采样选择模型和当前激活的声音后端。
3. 采样后端把音高、力度、方向和发声状态转换为根音选择、双层增益、重采样率与交叉淡化事件。
4. 采样输出、轻量松香噪声和伴奏汇入现有 master gain。
5. 静音、页面隐藏和销毁继续释放所有音源，避免卡音。

## 错误处理

- manifest 缺失、哈希不一致或输出文件缺失：导入/测试失败，不进入构建。
- 运行时网络或解码失败：保持合成回退，记录具体失败文件，不重复请求造成循环。
- 部分采样成功但集合不完整：不启用采样后端，避免演奏中途音色不一致。
- 页面切换输入模式或隐藏：停止所有采样 source，并清空续接计划。
- 浏览器不支持 MP3 解码属于回退条件；目标 Chromium 浏览器必须通过。

## 测试策略

测试先于生产代码编写：

- 根音选择覆盖当前八个可演奏音符，最大移调不超过两个半音。
- `p/f` 等功率混合在 0、0.5、1 强度下保持有限且单调。
- 换弓、换音、重新发声会请求新弓头；同方向同根音的普通帧不会反复重启。
- 长音续接只在样本余量进入阈值且声音仍激活时触发。
- 采样未就绪或失败时选择合成后端；完整就绪后选择采样后端。
- 资产测试核对 12 个输出文件、许可证、manifest、SHA-256 和总字节预算。
- 完整运行现有手势、引导曲、MIDI、场景和构建测试，保证节奏与计分无回归。

浏览器验收使用同一自动演示分别打开默认地址和 `?tone=synth`：

- 首次点击立刻有声音，采样切换没有明显断音。
- 八个音符没有显著的卡顿、音高错误或音量跳变。
- 换弓有真实起音，但没有爆音或重复触发。
- 连续拉弓超过单个样本长度时不中断。
- 摄像头和鼠标排练的手势到声音响应保持同步。

## 完成标准

- 默认演奏实际使用 VSCO 采样，合成音色只作为加载和失败回退。
- 12 个采样总传输体积不超过 1.5 MB。
- 音高误差与官方根音映射一致，当前音域最大转调不超过两个半音。
- 换音、换弓、续接和释放没有可听见的数字爆音。
- 自动化测试与生产构建全部通过。
- 新测试预览与上一版保留独立链接，用户可以直接做 A/B 听感比较。
