# 摄像头演奏舞台、环形节拍轨与 MIDI 导入设计

**日期：** 2026-07-21  
**状态：** 用户已确认，等待书面规格复核  
**工作分支：** feature/gesture-violin-mvp

## 1. 目标

把当前“深色舞台、中央虚拟提琴、摄像头缩略图”升级为增强现实演奏舞台：镜像摄像头成为全屏背景，虚拟提琴和琴弓位于画面右侧，音符沿提琴外圈形成环形节拍轨。同时降低单手追踪延迟，建立可扩展到双手的追踪接口，并用开源 MIDI/MusicXML 建立可复核的曲谱导入链路。

第一版必须同时改善视觉演奏感、换弓读拍和手势响应，不能以增加视觉效果为代价牺牲追踪稳定性。

## 2. 第一版范围

- 摄像头全屏背景与右侧虚拟提琴舞台。
- 环形音符/换弓轨和底部小节总览。
- GPU 优先、低分辨率输入、新视频帧驱动的单手识别。
- 快速换弓时更灵敏、静止时更稳定的自适应平滑。
- 追踪层改为手数组与左右手元数据，本轮仍只选择一只主控手。
- 建立离线 MIDI 导入工具，验证 Mutopia《欢乐颂》和《D 大调卡农》。
- 为曲目保存来源、许可证、导入参数和编配说明。

## 3. 非目标

- 本轮不启用双手玩法，不把 numHands 默认值改为 2。
- 不模拟真实小提琴指板指法或单根手指按弦位置。
- 不把完整外部曲库放进产品仓库，不在浏览器读取用户本地曲库。
- 不把带自由速度、错音或踏板的演奏 MIDI 直接作为节奏判定谱。
- 不重写 Web Audio 合成器、计分公式或 Three.js 小提琴几何。
- 不上传、录制或发送摄像头画面。

## 4. 演奏舞台

### 4.1 图层与空间

舞台从后到前依次为镜像摄像头、视频调色层、透明 Three.js 画布、环形节拍轨和边缘 HUD。视频使用 object-fit: cover 铺满画面，采用低饱和、轻对比、暖色调和边缘暗化，人物可辨识但不与橙红色乐器争夺焦点。

提琴固定在桌面宽屏右侧约 65%–92% 的安全区，琴弓横跨右侧演奏区。人物主要安全区位于左中部。曲名、下一弓和当前音放在左侧边缘，不覆盖面部与双手。

### 4.2 降级路径

鼠标排练、自动演示、摄像头拒绝或启动失败时恢复现有深色纹理背景。视频层隐藏，但提琴、环形轨和 HUD 继续工作。错误状态保留“重试摄像头”和“鼠标排练”入口。

### 4.3 响应式布局

窄屏时提琴缩小并移至右下安全区，环形轨减少可见音符数，左侧曲目信息压缩。底部总览保持可见，任何断点都不能把判定区移出视口或产生横向滚动。

## 5. 环形节拍轨

判定区固定在环形轨靠近琴弓的左下象限。未来音符沿顺时针方向进入判定区，已判定音符在短历史区内淡出。默认只显示未来 4–6 拍和少量历史。

每个音符使用弧段表达：

- 弧长表达持续拍数，并设置视觉最小值和最大值。
- 音名显示在弧段外侧。
- 箭头或端点朝向表达期望换弓方向。
- 当前判定窗口使用暖橙色辉光。
- Perfect、Good、Miss 使用短促颜色脉冲后淡出。
- 命中点与琴弓视觉接触点对齐，画面中只保留一个“现在”。

轨道几何由纯模型生成，输出角度、弧长、状态和文本。视图层只负责渲染，不重复推导音乐时间。

底部总览显示小节刻度、乐句分段、当前小节、完成范围和总拍数；速度或拍号变化使用离散标记。它只提供全局位置，不承担逐音符判定。

Three.js 和琴弓按显示刷新率更新。轨道 DOM 只在音符索引、判定或低频进度变化时更新，位置运动使用 CSS 自定义属性和 transform，不在追踪循环中重建整棵节点树。

## 6. 低延迟追踪

### 6.1 摄像头与推理

- 摄像头请求 640×480、理想 30–60 fps，并允许设备回退。
- Hand Landmarker 首选 GPU delegate；初始化失败时记录原因并创建 CPU 实例。
- 优先使用 requestVideoFrameCallback 触发识别；不支持时以 video.currentTime 去重。
- 识别与 Three.js 渲染解耦。渲染使用最近一次有效追踪结果，不因摄像头帧率降低而停止。
- 默认仍为 numHands: 1，现有置信度和释放语义通过测试锁定。

### 6.2 自适应平滑

固定 55 ms 时间常数会在快速换弓时产生滞后。新平滑器根据横向速度调节响应：静止和慢速移动使用较强平滑，快速移动和方向反转时提高响应系数。速度估计使用真实视频帧时间戳，禁止用重复渲染帧制造虚假速度。

平滑器保持独立状态，并覆盖静止抖动、快速扫动、方向反转、低帧率和追踪丢失测试。

### 6.3 丢帧与诊断

单个缺失检测帧不立即清空视觉位置；短暂缺失时保持最后位置并降低置信度。明确低置信度、超过短宽限期或摄像头停止时立即释放音频，防止卡音。宽限只服务视觉连续性，不能让无手状态持续发声。

追踪器暴露 delegate、推理耗时、检测频率和最近视频帧时间。正常 HUD 只显示追踪质量，详细值通过调试查询参数显示。每个追踪帧不得写控制台日志。

## 7. 双手接口预留

追踪层返回稳定排序的手数组，每只手包含 landmarks、handedness、confidence 和视频时间戳。主控选择器在本轮从数组中选一只手交给现有 BowingGestureInterpreter；音乐、音频和场景层继续消费单个 BowingFrame。

未来双手推荐分工：

- 右手负责拉弓方向、速度、力度和连续性。
- 左手自由演奏负责音区/琴弦与揉弦或音色。
- 左手曲目演奏不覆盖 MIDI 基础旋律，只贡献表现分和音色，避免初学者因左手误差中断曲目。
- handedness、画面位置和短时角色锁共同防止交叉时角色跳变。

双手玩法需要单独规格、性能基准和用户确认，不随本轮接口重构自动开启。

## 8. MIDI 曲谱导入

### 8.1 来源

第一版验证两份 Mutopia MIDI：

- Beethoven《Ode to Joy》：Public Domain，Mutopia ID 528。
- Pachelbel《Canon in D》：CC BY 3.0，Mutopia ID 1700，必须保留署名和来源。

两份小型原始 MIDI 与许可证说明进入项目仓库。完整 Mutopia、ASAP 和 MTG 数据集只保留在用户指定的曲谱收集目录，不纳入应用构建。

### 8.2 离线转换

Node/TypeScript 导入命令读取 MIDI，输出项目内部曲目数据：

1. 解析 tempo、time signature、track、program、note、velocity 和 duration。
2. 显式选择旋律声部；多声部文件不能默认取最高音。
3. 将事件映射到拍单位，保留速度与拍号变化。
4. 按明确起止小节生成教学片段，不暗中删除或重排音符。
5. 输出旋律、伴奏、来源、许可证、导入参数和源文件摘要。
6. 验证重叠音、空小节、非法速度、越界音域和非单调事件。

浏览器只加载生成后的静态 TypeScript/JSON，不解析外部目录，也不依赖本地绝对路径。

“准确”表示来源可追踪，音高、时值、拍号与选定数字谱一致，并通过逐小节复核；不等于未经适配地采用全部声部。移调、删减小节和伴奏变化必须写入编配说明。

ASAP 的 235 份量化 score MIDI/MusicXML 可用于后续钢琴曲扩展，但 CC BY-NC-SA 4.0 限制商业使用。MTG 数据用于演奏研究，不作为本轮产品曲谱来源。

## 9. 组件边界

- HandTracker：摄像头、MediaPipe 初始化、新视频帧识别和诊断。
- 主控手选择器：从手数组稳定选择单手角色。
- 自适应平滑器：从手掌位置与视频时间生成控制值。
- 环形轨模型：从歌曲和播放帧生成纯几何/状态数据。
- 环形轨视图：渲染弧段、命中区、反馈和底部总览。
- AppView：视频背景、调色层、降级背景和边缘 HUD。
- MIDI 导入命令：外部 MIDI 到内部曲目数据的离线转换。
- 曲目验证器：运行时契约与来源元数据检查。

追踪器不读取歌曲，轨道模型不访问 DOM，MIDI 导入器不进入浏览器包。

## 10. 错误处理

- GPU 初始化失败：自动回退 CPU，记录诊断但不阻止体验。
- 摄像头失败：隐藏视频，恢复深色舞台并提供重试和鼠标排练。
- 视频尺寸或新帧不可用：不重复推理，音频按丢帧规则释放。
- MIDI 缺少旋律声部、拍号非法或事件重叠：导入失败并报告文件、轨道和事件位置。
- 许可证或来源元数据缺失：导入验证失败。

## 11. 测试与验收

自动测试覆盖：

- GPU 失败到 CPU 回退。
- 重复 video.currentTime 不重复推理。
- 主控手在置信度变化和短暂交叉时保持稳定。
- 自适应平滑的静止、扫动、反转、低帧率和丢失。
- 环形轨角度、弧长、未来/历史裁剪和判定状态。
- 底部小节刻度、乐句范围和进度。
- 两首 MIDI 的来源、许可证、旋律声部、拍号、速度与片段摘要。
- 全部现有手势、音乐、音频和曲目测试继续通过。

浏览器验收覆盖：

- 桌面 Chrome/Edge 中人物位于左中部，提琴和环形轨位于右侧。
- 摄像头、鼠标排练和 ?demo=1 均可完成两种演奏模式。
- 快速反向换弓比当前版本更贴手，静止时无明显抖动发声。
- CPU 回退、拒绝权限和摄像头断开均有可用降级。
- 16:9、用户当前截图比例和窄屏无横向滚动，判定区始终可见。
- 自动演示截图做视觉回归，真实摄像头至少进行一次人工复核。

性能验收：

- 不对重复视频帧运行 MediaPipe。
- 不在每个追踪帧重建轨道 DOM。
- 正常机器优先 GPU，CPU 回退仍可演奏。
- 测试、类型检查和生产构建通过；MIDI 导入依赖不进入浏览器主包。

## 12. 发布顺序

1. 追踪循环、GPU/CPU 回退和诊断。
2. 手数组接口、主控手选择与自适应平滑。
3. 摄像头全屏舞台和右侧提琴布局。
4. 环形节拍轨和底部小节总览。
5. MIDI 导入、两首来源曲谱和许可证元数据。
6. 自动测试、浏览器验收、性能对比和 Netlify 更新。

每一步保持鼠标排练和自动演示可用，避免只能在真实摄像头环境发现回归。
